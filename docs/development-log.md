## 일하는 방식

**커밋과 주석에 "왜"를 남깁니다.** 증상, 원인, 해결을 커밋 메시지와 주석에 적어 두어 같은 코드를 다시 볼 때 판단 근거를 찾지 않아도 되게 했습니다. 예를 들면 이런 식입니다.

```
fix: 모든 페이지가 홈을 canonical 로 가리키던 문제

루트 메타데이터의 alternates.canonical 이 하위 페이지로 그대로 상속돼
/explore, /series, /notices 까지 canonical 이 홈으로 찍히고 있었다.
구글에 "이 페이지들은 홈의 중복본"이라고 말하는 셈이라 색인에서 빠진다.
```

**배포는 자동으로, 되돌리기는 태그로 합니다.**
- `main`에 반영되면 GitHub Actions가 Docker 이미지를 만들어 GHCR에 올립니다.
- EC2는 이미지를 받아 기동만 하고, 헬스체크로 확인합니다.
- 릴리스마다 버전 태그를 남겨 이전 이미지로 바로 되돌릴 수 있습니다.

**브랜치와 데이터를 분리합니다.** `main`을 배포 기준으로 두고, 개발용 `dev`는 `main`과 같게 유지합니다. DB 덤프 같은 데이터 작업은 `dev`에서만 합니다.

**테스트는 규칙이 있는 곳에 둡니다.** 인증, 이벤트 집계, 메일 수신 동의처럼 규칙이 분명한 서비스 로직은 단위 테스트로 확인하고, 통합 테스트는 개발 DB와 섞이지 않게 전용 DB를 씁니다.

**AI 코딩 도구를 씁니다.** Cursor와 Claude Code로 구현 속도를 높이고, 코드 스타일 규칙은 도구 설정 파일로 관리합니다.
