# SEO 문제 해결 기록

blogstudio는 처음에 로그인해야 볼 수 있는 서비스였습니다. 2026년 8월 19일 비로그인 열람으로 바꾸면서 검색 유입을 열었고, 이후 8월 25일부터 9월 1일까지 색인을 막고 있던 문제를 차례로 찾아 고쳤습니다.
각 항목의 인용문은 당시 커밋 메시지에서 그대로 가져왔습니다.

---

## 1. 검색 결과에 로그인 화면이 잡힘

- **증상**: 구글 검색 결과의 설명이 "이메일 또는 휴대폰 번호. 비밀번호. 로그인"으로 나왔습니다.
- **원인**: 로그인해야 볼 수 있던 시절에 크롤러가 수집할 수 있는 화면이 로그인 페이지뿐이었습니다.
- **해결**
  - 사이트 제목·설명·대표 이미지를 제대로 채웠습니다.
  - `robots.ts`를 추가해 로그인 전용 화면(`/my`, `/settings`, `/editor` 등)과 모바일 미러(`/m/`)를 크롤링에서 뺐습니다.
- **코드**: [robots.ts](../web/src/app/robots.ts), [app/layout.tsx](../web/src/app/layout.tsx)

## 2. 구글봇이 robots에 막혀 사실상 전 페이지 크롤링 실패

- **증상**: Search Console에서 "robots.txt에 의해 차단됨"이 대부분의 페이지에 떴습니다.
- **원인**: 모바일 기기는 미들웨어가 `/m` 주소로 리다이렉트하는데, 구글봇 스마트폰 UA에도 `Android`·`Mobile`이 들어 있어 똑같이 `/m`으로 보내졌습니다. 그런데 robots가 중복 문서를 막으려고 `/m`을 차단하고 있었습니다.

  > 구글은 기본이 모바일 우선 크롤링이라 사실상 전 페이지가 색인되지 못했다.

- **해결**: 검색엔진과 SNS 미리보기 봇은 모바일 리다이렉트 대상에서 뺐습니다. 공유 카드가 깨지는 것도 같은 이유였습니다.

  ```ts
  // 크롤러는 모바일이어도 /m 으로 보내지 않는다
  const isMobile =
    isMobileUserAgent(userAgent) && !isCrawlerUserAgent(userAgent);
  ```

- **코드**: [middleware.ts](../web/src/middleware.ts)

## 3. 모든 페이지가 홈을 canonical로 가리킴

- **증상**: `/explore`, `/series`, `/notices` 같은 하위 페이지의 canonical이 전부 홈 주소였습니다.
- **원인**: 루트 레이아웃 메타데이터의 `alternates.canonical`이 하위 페이지로 그대로 상속됐습니다.

  > 구글에 "이 페이지들은 홈의 중복본"이라고 말하는 셈이라 색인에서 빠진다.

- **해결**: 루트에서 canonical을 지웠습니다. 값이 없으면 각 페이지가 자기 주소를 canonical로 씁니다. 같은 글이 두 주소로 열리는 글 페이지만 직접 지정했습니다.
- **코드**: [app/layout.tsx](../web/src/app/layout.tsx)

## 4. 글마다 제목·설명이 같고 본문이 색인되지 않음

- **증상**
  - 모든 글이 홈과 같은 제목·설명을 달고 있어서 검색 결과에서 서로 구분되지 않았습니다.
  - Search Console 실시간 테스트에서 "글을 불러오는데 실패"가 떴고, 제목만 색인되고 본문 문장으로는 검색되지 않았습니다.
- **원인**: 글 페이지가 클라이언트 컴포넌트라 메타데이터를 만들 수 없었고, 본문은 자바스크립트가 실행된 뒤에야 나타났습니다. 크롤러는 렌더링 시간 예산이 있어서 그 전에 잘리는 일이 잦습니다.
- **해결**: 페이지 코드는 그대로 두고, 서버 컴포넌트인 레이아웃이 그 일을 대신하게 했습니다.
  - `generateMetadata`로 글마다 제목, 설명(160자), canonical, Open Graph, Twitter 카드를 붙입니다.
  - `BlogPosting` JSON-LD를 넣습니다. 본문은 싣지 않습니다(유료 글이 노출되기 때문).
  - 서버에서 본문을 한 번 그려 둡니다. 페이지가 본문을 다 그리면 `html[data-article-ready]`가 붙어 서버 블록은 숨겨지므로, 사용자에게 같은 글이 두 번 보이지 않습니다.
  - **유료 글은 본문 대신 요약만** 그립니다. 서버 응답에 전체 본문이 실려 오더라도 여기서 그리면 결제 없이 읽히게 됩니다.
  - 글을 읽을 때 **조회수를 올리지 않습니다**. 크롤러가 훑을 때마다 조회수가 뛰면 인기글 순위가 망가집니다.
  - 조회에 실패해도 예외를 던지지 않습니다. 메타데이터가 없는 건 아쉬운 정도지만, 여기서 오류가 나면 글 페이지 자체가 열리지 않습니다.
- **코드**: [article/[id]/layout.tsx](../web/src/app/article/%5Bid%5D/layout.tsx)

## 5. 사이트맵 문제

| 문제 | 원인 | 해결 |
|---|---|---|
| 글 주소가 0건 | API 주소 환경 변수가 `/api`로 끝나기도 하고 아니기도 해서 요청 경로가 어긋남 | 어느 쪽이든 맞게 정규화 |
| 404 주소 포함 | `/series`는 목록 페이지가 없는데 사이트맵에 있었음 | 실제로 200을 주는 주소만 싣기 |
| 리다이렉트 주소 포함 | 루트(`/`)는 미들웨어가 `/home`으로 보내는데 둘 다 실림 | 루트 제거 |
| (예방) API가 죽으면 사이트맵 전체가 500이 될 수 있음 | 글 목록 조회 실패가 그대로 전파되는 구조 | 실패하면 고정 경로만으로라도 사이트맵을 내보냄 |

> 없는 주소가 섞이면 구글이 오류로 기록하고 사이트맵 전체 신뢰도가 떨어진다.

- **코드**: [sitemap.ts](../web/src/app/sitemap.ts)

## 6. 작가 페이지가 robots에 막힘

- **증상**: 작가 소개 페이지(`/author/...`)가 색인에서 통째로 빠졌습니다. 모바일에서는 작가 페이지가 스크롤되지 않는 문제도 함께 있었습니다.
- **원인**: 둘 다 같은 접두사 충돌이었습니다. `/author`는 `/auth`로 시작합니다.
  - robots의 `/auth`가 `/author`까지 막고 있었습니다.
  - 화면 코드는 `startsWith`로 로그인 페이지를 판정해서, 작가 페이지를 로그인 페이지로 잘못 취급하고 화면을 잠갔습니다.
- **해결**: robots는 `/auth/`로 고쳤고, 경로 접두사 검사는 모두 구분자(`/`)까지 맞춰 비교하도록 바꿨습니다.
- **코드**: [robots.ts](../web/src/app/robots.ts), 같은 방식의 경로 판정: [auth-routes.ts](../web/src/lib/auth-routes.ts)의 `matchesPath`

## 7. 한글 이름으로 검색되게

- 사이트 제목을 "블로그스튜디오 (blogstudio)"로 바꾸고, `WebSite`·`Organization` JSON-LD에 `alternateName`으로 영문·띄어쓰기 표기를 함께 넣었습니다.
- `/favicon.ico`가 404라서 검색 결과에 아이콘이 없었습니다. 여러 크기를 담은 ico와 큰 PNG를 함께 알렸습니다.
- **코드**: [app/layout.tsx](../web/src/app/layout.tsx)

## 남은 과제

- **모바일 미러(`/m`) 구조**: 같은 내용을 두 주소로 제공하는 구조라, 지금은 robots로 `/m`을 막고 크롤러를 리다이렉트에서 빼는 방식으로 대응하고 있습니다. 근본적인 해결은 반응형 단일 URL로 합치는 것입니다.
- **서버 렌더링 본문 블록**: 글 페이지가 클라이언트 컴포넌트라서 레이아웃이 같은 본문을 한 번 더 그리는 방식입니다. 페이지를 서버 컴포넌트로 옮기면 필요 없어집니다.
- **정리한 것 (2026.11)**: 구조화 데이터의 `SearchAction`을 지웠습니다. 가리키던 `/search`가 404였고, 구글도 사이트링크 검색창을 종료했습니다.
